## 统一计算合同

```text
Sigma = (Q3 - Q1) / 1.35
LCL = 中位数 - 6 × Sigma
UCL = 中位数 + 6 × Sigma
```

身份列 `NUM`、`lot_ID`、`周记`、`批次` 不参与统计。每个参数的 count、mean、sample std、min、Q1、median、Q3、max、Sigma、LCL、UCL 均基于目标目录内该参数的全部有效数值计算，不对分文件统计量做平均。

## 实现结果

- 新增 `shared/pat_engine.py`，负责低内存数值暂存、参数结构核对、精确统计和统一 PAT 表头。
- 日月新继续复用现有 DC/DVDS/RG 提取规则；新增产品身份一致性检查和产品根目录/单类型目录发现。
- 电基继续复用 Source Registry 和四类严格解析器；一次 PAT 只接受同一产品、同一格式。
- 参数结构在同一分组内发生漂移时拒绝计算；不同分组出现同名参数时拒绝重复计数。
- 临时参数文件位于用户选择的输出根目录下，并在成功或异常退出后由临时目录上下文自动清理。

## 做得较好的部分

- 没有重写各厂成熟的原始文件解析和清洗语义，只把数值汇总与统计计算统一。
- 电基 PowerTECH XLSX 使用真实清洗结果做逐值回归，证明读取路径变化没有改变 PAT 数值。
- 低内存设计不保留全部参数矩阵；最终统计时一次只加载一个参数的连续 `float64` 数值。

## 不确定性与限制

- 日月新产品身份当前依赖已验证的 `NCE...-封装码` 文件名；无法识别产品的文件会停止，不会猜测。
- 电基产品根目录若同时包含 DC 与 TF 两种源格式，应分别选择各自目录计算，不能混合。
- 已清洗 Excel 的旧后端函数暂时保留作兼容和回归用途，但 GUI 已统一为原始目录直读。
- 集佳如需 PAT，需先确认其业务上是否使用相同参数范围和源目录合同，再单独启用。

## 后续建议

- 新增封装厂 PAT 时，只实现严格的原始目录发现和单文件解析适配，并复用统一 PAT 核心。
- 对新增源格式继续执行真实源文件与既有清洗结果逐参数对账，未知产品、格式、单位和结构保持 fail closed。
