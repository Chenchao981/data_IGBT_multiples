# 电基 dj8 PowerTECH 身份兼容完成报告

日期：2026-08-28
版本：v2.18.0

## 完成范围

- 复现并修复 `dj8` PowerTECH 伪 `.xls` 文件无法解析的问题。
- 保留既有 PowerTECH `standard-34` 参数、单位、行保留、规格和散点图合同，不新增 GUI 入口或平行解析器。
- 为“外部文件名省略产品、可带数字复制后缀 `(n)`”增加严格的元数据身份回填。
- 更新自动化测试、项目说明、用户文档、版本号和可交付 PYZ。

## 根因与事实

真实样本 `M260616003-001 C207458.07 DC260716024650(1).xls` 不是 Excel 工作簿，
而是首行签名为 `PowerTECH Test System` 的 GB18030、Tab 分隔文本。Source Registry
能够正确识别为 `powertech_text`，失败发生在测量头部读取之前：旧文件名规则强制要求
`<产品>_` 前缀，且不接受 Windows 数字复制后缀 `(1)`。

源文件内存在完整且可交叉验证的身份：

- `DataFileName`：制造批次、批次和测试标签时间；
- `TestFileName`：精确测试程序及产品 `NCEAP020N10LL(M)-7E00`；
- `Lot`：制造批次 `M260616003-001` 和批次 `C207458.07`；
- Item：与既有 `standard-34` 布局完全一致。

因此本次问题属于身份来源变化，不是编码、参数布局、单位或数据行格式变化。

## 实现结果

- `parse_powertech_file()` 先读取并定位 PowerTECH 头部，再解析身份。
- 原有带产品前缀的文件名规则保持不变；只有原规则失败且外部文件名精确匹配
  `<制造批次><批次><测试标签时间>(n)` 时才进入 dj8 回填路径。
- 外部文件名与 `DataFileName` 的制造批次、批次和测试标签时间必须完全一致。
- `TestFileName` 必须等于配置中精确登记的测试程序，产品不从任意字符串猜测。
- `(n)` 只接受正整数复制后缀；非数字后缀继续拒绝。
- 通过上述校验后仍执行既有 `Lot`、Item 数量/顺序、Bias、单位和多文件 Schema 校验。

## 不确定性与限制

- 当前只有一个 dj8 真实测试程序得到批准；同产品的新程序版本仍会失败关闭，需要新样本确认后登记。
- 当前只批准正整数形式的复制后缀 `(n)`；其他人工备注、设备标签或文件名变体不会自动接受。
- 真实验证覆盖一个文件和一个批次；多文件合并继续依赖既有单产品、单 Schema 严格规则。
