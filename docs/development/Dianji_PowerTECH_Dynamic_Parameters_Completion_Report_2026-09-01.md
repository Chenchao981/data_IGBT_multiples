# 电基 PowerTECH 动态参数兼容完成报告

日期：2026-09-01
版本：v2.19.0

## 完成范围

- 将 PowerTECH 伪 `.xls` 文本和原生 `.xlsx` 的业务参数解析从固定列数/固定列号改为
  `Item Name + Bias1-3 + Unit` 语义规划。
- 后续测试程序在右侧增加的业务参数自动进入 RAW、Spec、FT 散点和原始目录 PAT。
- 同一产品、同一 PowerTECH 格式允许严格的右侧参数扩展；旧文件缺少的新参数补
  `NaN`，不补 0。
- `CONT*`、`SAME`、`DELAY`、`VF_EX`、`VFSE`、`EAS`、`RF-SCANBOX`、
  `CISS_EX`、`DVF_EX`、`TSD` 和结构识别出的预筛 VTH 继续排除。
- 保留既有 19/21 参数的名称、顺序、单位换算、行保留、规格和散点合同。
- 同步登记 dj9 的 M08M15 精确 `TestFileName`，并补齐 dj1 已验证的 `(n)` 复制后缀和
  `E002413.00` 批次边界。
- STS8203 和 DP1205 TF 不使用 PowerTECH Item/Bias 结构，继续保持原严格 Schema。

## 根因

原程序有三处静态门槛：

1. PowerTECH 文本解析器只接受 32/34 个 Item，并从固定 Item 号取值；
2. PowerTECH XLSX 只按 34/35/38/39 项完整布局输出；
3. FT-ALL 合并器和原始目录 PAT 要求每个文件的参数列完全相同。

真实数据证明 Item 头部、Bias、单位和数据列始终物理对齐，但程序之间的控制占位项和
业务参数数量会变化。继续把 Item 总数作为数据合同，会把右侧新增的合法参数误判为
未知格式。

## 实现结果

### 动态参数规划

- 新增共享 `powertech_items.py`，两类 PowerTECH 共同使用同一套动态选择、命名、
  单位和语义 Key 规则。
- Item 编号必须唯一、连续，Item/Bias/Min/Max/Unit 头部必须物理对齐。
- 已知参数继续使用稳定业务名，例如 `DVDS(mV)`、`Rg(R)`、`IDSS80(nA)`；
  `A/uA -> nA` 等换算明确执行，未知单位不猜测。
- 未知但非控制的新业务参数保留源参数名、Bias 和源单位，换算因子为 1。
- DELTA 的身份按其引用的 BVDSS/VTH 语义归一，不把会随占位项变化的原始 `#Item`
  编号写入 Schema Key，因此 32/34 项旧程序仍可合并。
- 同名输出若 Bias、单位或原始语义不同则停止；不会静默覆盖或错列。

### 合并、散点和 PAT

- PowerTECH 使用 `nested-prefix` 合同：短 Schema 必须是长 Schema 的严格前缀。
- 选择最长 Schema 作为本次输出列，短文件使用 `reindex` 补空值。
- 中间插入、删除、改名、重排或语义冲突仍失败关闭。
- 原始目录 PAT 只为 PowerTECH 启用同一规则；新增参数仅统计实际包含该参数文件中的
  有效值。其他厂家和电基 STS/TF 仍使用 `exact`。

## 确定的边界

- 参数“动态”不等于身份放宽：文件名、Lot、DataFileName、TestFileName、产品、机台和
  已知参数单位仍严格校验。
- 只接受旧参数序列的右侧扩展；中间改变不是本次兼容范围。
- 未知新参数不会自动猜测单位换算；需要业务确认后才能升级为已知参数规则。

## 不确定性与限制

- 当前真实伪 `.xls` 最大 34 个 Item，真实 XLSX 最大 39 个 Item；“右侧再增加业务参数”
  来自用户确认的后续格式规则，本次通过合成追加 Item 完整验证，但尚无对应真实新文件。
- XLSX 仍要求已验证核心程序与文件/机台身份；动态参数不会把完全不同的测试程序当作
  同一格式。
