# 杰群 DC-AI 清洗入口合并完成报告

> 后续修订：v2.14.1 已恢复 `DVDS`、`RG` 专用按钮。原因是纯 DVDS/RG 目录没有 DC
> 参数，不能交给 DC-AI 识别。本报告中的“一键产品根目录”能力仍然有效，但“唯一入口”
> 结论已被后续版本替代。

- 完成日期：2026-08-25
- 发布版本：v2.14.0
- 范围：杰群 GUI 清洗入口及 DC-AI 后端编排

## 1. 交付结论

杰群“FT 数据清洗”已由六个按钮精简为唯一 `DC-AI` 按钮。用户选择一个明确的原始数据目录后，程序自动识别格式并清洗实际存在的数据：

- 分目录格式：自动连续清洗 DC、DVDS、RG。
- 统一 CSV：沿用既有统一清洗器，输出 DC、DVDS、RG。
- 第三产线平铺格式：只清洗实际存在的 DC。

PAT 和 SYL&SBL 仍是独立业务入口，不受本次调整影响。

## 2. 稳定性设计

- 只做后端编排，不改写 DC、DVDS、RG 的解析、参数选择、单位换算和 Excel 输出规则。
- 自动识别仍只读取目录结构及 DTA `Item` 头部，数据清洗读取量与原来分别点击三次相同。
- 分目录格式在写出结果前先发现并校验可配对的 DVDS/RG 目录。
- 发现多个可能配对的 DVDS 或 RG 目录时停止，不猜测产品归属。
- 缺少 DVDS 或 RG 目录时不报错，只处理实际存在的数据。
- DC-3 不搜索或误并入 DVDS/RG。

## 3. 真实数据验证

样本：`NCEAP065NHD40AG(M)-1J00 JQ PAT`

| 类型 | 文件数 | 输出行数 | 输出列数 |
| --- | ---: | ---: | ---: |
| DC | 2 | 201,769 | 32 |
| DVDS | 2 | 208,296 | 3 |
| RG | 2 | 203,640 | 3 |

分别执行原有三个清洗器作为基准，再通过新版 `DC-AI` 单次执行。三份对应工作簿的工作表 XML、共享字符串和样式 SHA256 比较均完全一致，证明合并没有改变数据或格式。

## 4. 性能判断

- 自动识别新增的成本仅为文件列表和头部扫描，相比 60 多万行解析及 Excel 写入可忽略。
- 真正耗时仍是 DC 大表写入 Excel；真实样本 DC 约 20 万行，写入约 60～70 秒。
- 合并后总计算量与原来按 DC、DVDS、RG 分别点击相同，但减少人工选择和等待三次的操作成本。

## 5. 自动化与发布验证

- 增加分目录自动发现、三类顺序调用、DC-3 不调用附加清洗器等测试。
- 完整测试集、编译检查、发布包内容审计及打包版 GUI 验收在发布前执行。
- 发布包不包含真实 CSV、Excel 验证结果、日志、缓存或临时文件。

## 6. 已知边界

- DC、DVDS、RG 继续沿用各自的防覆盖流水目录，因此一次 DC-AI 可能在输出目录生成三个连续编号的结果文件夹；这是原有输出契约，没有为界面精简而改变。
- 若用户选择同时包含多个产品、多个同名 DVDS/RG 子目录的上级总目录，程序会停止并要求缩小到一个产品范围。
- 某一清洗器在数据读取阶段失败时，之前已经成功写出的结果不会自动删除，状态区会明确报告完整任务未完成。
